# 유사도 임계값 실측 — 0.6 → 0.48

> phase-08 §3.2가 요구하는 근거 문서. "임계값 `0.6`은 설정값. 실측 후 조정하고 근거를 문서화"
> 측정: `ai-service/tests/test_embedding_e2e.py` (실제 bge-m3 + 실제 pgvector)

## 결론

**FSD §10.2의 기본값 0.6은 이 파이프라인에서 너무 높다.** 0.48로 낮췄다.

0.6을 그대로 쓰면 **답할 수 있는 질문 10건 중 4건이 임계값에서 잘려나간다.**
검색은 정확히 맞는 페이지를 1위로 찾아왔는데도 LLM을 호출하지 않고
"제공된 투자설명서에서 확인할 수 없습니다"를 반환한다.

## 측정 조건

| | |
|---|---|
| 임베딩 모델 | `BAAI/bge-m3` (1024차원, L2 정규화) |
| 벡터 연산 | pgvector 코사인 거리 `<=>`, 유사도 = `1 - 거리` |
| 인덱스 | `hnsw (embedding vector_cosine_ops)` |
| 코퍼스 | 투자설명서 3페이지 발췌 (p.3 기초자산 / p.7 위험요인 / p.12 청약·배당) |
| 하드웨어 | Ryzen 5 5625U, CPU 추론 |

코퍼스가 3청크로 작다. 실제 투자설명서를 인덱싱한 뒤 재측정이 필요하며,
그때는 이 문서와 `SIMILARITY_THRESHOLD`를 함께 갱신한다.

## 결과

### 답이 문서에 있는 질문 (10건) — 전부 올바른 페이지를 1위로 검색

| 질문 | 1위 페이지 | 유사도 | 0.6 기준 |
|---|---|---|---|
| 원금 손실 가능성이 있나요? | p.7 | 0.654 | 통과 |
| 목표 배당수익률이 몇 퍼센트인가요? | p.12 | 0.650 | 통과 |
| 건물 연면적이 얼마인가요? | p.3 | 0.621 | 통과 |
| 기초자산 건물은 어디에 있나요? | p.3 | 0.617 | 통과 |
| 조각당 공모가는 얼마인가요? | p.12 | 0.615 | 통과 |
| 배당은 얼마나 자주 주나요? | p.12 | 0.606 | 통과 |
| 금리가 오르면 어떤 영향이 있나요? | p.7 | 0.580 | **차단** |
| 공실이 생기면 어떻게 되나요? | p.7 | 0.550 | **차단** |
| 주요 위험요인이 무엇인가요? | p.7 | 0.546 | **차단** |
| 임차인은 몇 개사인가요? | p.3 | 0.527 | **차단** |

**검색 정확도 10/10.** 페이지는 전부 맞았고, 문제는 임계값뿐이다.

특히 "주요 위험요인이 무엇인가요?"(0.546)가 잘리는 것이 치명적이다.
FSD §10.3이 "위험 관련 질문에는 해당 위험요인 원문 요약을 우선 제시"를
요구하는데, 0.6에서는 그 질문이 LLM에 도달하지 못한다.

### 주제가 무관한 질문 (7건)

| 질문 | 최고 유사도 |
|---|---|
| 환불 규정이 어떻게 되나요? | 0.429 |
| 작년 코스피 지수는 얼마였나요? | 0.410 |
| 이 상품의 담당 PM 연락처를 알려주세요 | 0.391 |
| 오늘 서울 날씨가 어떤가요? | 0.379 |
| 점심 메뉴 추천해 주세요 | 0.376 |
| 파이썬으로 리스트를 정렬하는 방법을 알려주세요 | 0.350 |
| 이 회사 대표이사의 취미가 무엇인가요? | 0.350 |

### 분포와 임계값 선정

```
무관 질문   0.350 ──────── 0.429
                              │ ← 간격 0.099
관련 질문                  0.527 ──────── 0.654

            0.429 ── 0.48 ── 0.527
                      ↑ 채택
```

| 후보 | 무관 최고(0.429) 대비 여유 | 관련 최저(0.527) 대비 여유 |
|---|---|---|
| 0.45 | +0.021 | −0.077 |
| **0.48** | **+0.051** | **−0.047** |
| 0.50 | +0.071 | −0.027 |

**0.48**을 택했다. 두 분포의 중간(0.478)에 가장 가깝다.

두 방향의 오류 비용이 대칭이 아니라는 점도 고려했다.
- 임계값이 **높으면** → 답할 수 있는 질문을 못 답한다. 복구 수단이 없다.
- 임계값이 **낮으면** → 무관한 질문에 LLM을 호출한다. 비용이 들지만,
  출력 가드레일의 인용 검증(`NO_CITATION` / `HALLUCINATED_CITATION`)이
  잘못된 답이 나가는 것은 막는다.

즉 낮은 쪽 실패는 **뒤에 안전망이 있고** 높은 쪽 실패는 없다.
그래서 정확히 중간이 아니라 중간보다 약간 위(0.48 > 0.478)에서 멈췄다.

## 임계값이 거르지 못하는 것 — 설계상 중요

측정 중에 분류를 잘못한 질문이 하나 있었다.

| 질문 | 최고 유사도 |
|---|---|
| 청약 경쟁률이 어떻게 되나요? | **0.604** |

관련 질문 10건 중 4건보다 높다. 문서에 경쟁률 정보는 **없는데도** 그렇다.
p.12 청크가 "**청약** 단위는 1조각이며…"로 시작해 `청약`이라는 단어를 공유하기 때문이다.

이건 임계값의 실패가 아니라 **임계값의 관할 밖**이다. 유사도가 거르는 것은
*주제적 무관함*이지 *답의 부재*가 아니다. 둘을 구분하지 않고 임계값을 올려
이런 질문까지 막으려 하면, 0.604 아래의 정상 질문 6건이 함께 잘려나간다.

답이 없는 on-topic 질문은 다른 층이 처리한다.

```
"청약 경쟁률?" → 유사도 0.604 → 임계값 통과 → LLM 호출
                → found_in_document: false → "확인할 수 없습니다"
                → (권유 표현이 섞이면) 출력 가드레일이 차단
```

`test_on_topic_question_passes_threshold` 가 이 경로를 고정한다.

## 재측정 방법

```bash
docker compose up -d postgres
cd ai-service
.venv/Scripts/python.exe -m pip install ".[embeddings]"
.venv/Scripts/python.exe -m pytest tests/test_embedding_e2e.py -q -s
```

`-s` 를 붙이면 위 표의 유사도가 그대로 출력된다.
`SIMILARITY_THRESHOLD` 를 바꾸면 테스트가 새 값 기준으로 검증한다 —
값이 두 분포 사이를 벗어나면 실패한다.

## 부수적으로 잡은 버그

이 e2e를 붙이면서 **운영 코드의 검색이 통째로 실패하는 버그**를 찾았다.

```
psycopg.errors.UndefinedFunction:
operator does not exist: vector <=> double precision[]
```

psycopg는 파이썬 `list[float]` 를 `double precision[]` 로 넘긴다.
`INSERT` 는 할당 캐스트로 통과하지만 `<=>` 연산자는 그 타입을 받지 않는다.
**인덱싱은 성공하고 검색만 실패하는** 형태라 대역(fake) 기반 테스트로는
드러나지 않았다. `%s::vector` 명시 캐스트로 고정했다
(`app/retrieval/search.py`, `app/indexing/service.py`).
