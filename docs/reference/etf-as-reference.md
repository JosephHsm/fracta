# ETF를 기초자산으로 쓰는 설계

> 왜 상장 ETF·리츠를 끌어왔는가, 그리고 그것으로 무엇을 증명하는가.
> 요약은 [README](../../README.md#왜-etf를-끌어왔는가)에 있고, 여기는 구현과 근거다.

## 전제 — 실거래가 없는 상품을 어떻게 검증하는가

토큰증권 유통 시장은 아직 없다. 그래서 조각증권에는 **"맞는 가격"이 무엇인지 알려주는
기준이 없다.** 이 프로젝트가 만드는 괴리율 엔진이 제대로 도는지 증명할 방법도 함께 없어진다.

FRACTA는 이 문제를 상장 자산을 기초자산으로 끌어와서 푼다.

**증권사에서 가져오는 것은 시세뿐이다.** 조각의 발행·청약·매매·결제는 전부 자체 원장과
오더북에서 처리한다. 증권사에 주문은 나가지 않는다 —
[네 겹으로 강제](../../README.md#실주문이-나갈-수-없는-이유)한다.

## 3층 구조

시드가 만드는 데이터는 세 층이다. 각 층이 화면에서 서로 다른 것을 증명한다.

| 층 | 자산 | 티커 | 화면에서 보이는 것 |
|---|---|---|---|
| ① ETF | KODEX 200 · TIGER 미국나스닥100 | 실연동 | 시세 차트 · 괴리율 · **이중 괴리율** |
| ② 리츠 | 신한알파리츠 · ESR켄달스퀘어리츠 | 실연동 | 시세 차트 · 괴리율 · 자동 거래중단 |
| ③ 실물 | 한남동 상업시설 + 모의 자산 61건 | **없음** | **괴리율도 차트도 없는 화면** |

③이 있어야 ①②의 의미가 드러난다. "왜 어떤 종목은 괴리율이 있고 어떤 건 없나"가
화면 자체로 설명된다. 참조가가 없는 자산은 조각투자의 예외가 아니라 **다수**다 —
미술품·저작권·실물 부동산이 전부 여기 속한다.

### 주문 가격은 참조가에서 파생시킨다

시드가 고정 가격을 쓰면 다음 날 시세가 움직였을 때 괴리율 상태가 재현되지 않는다.
그래서 실시세를 조회해 발행가를 맞추고, 체결가를 배수로 띄운다.

```
발행가 = round(조각 참조가)              참조가 = 원자산 시세 / 분할비율
체결가 = 발행가 × premium               1.02 정상 · 1.16 경고 · 1.27 중단
```

2026-09-03 실행 결과 — KODEX 200 +2.03% · TIGER +15.97% · 신한알파리츠 +0.93% ·
ESR켄달스퀘어리츠 +26.92%(→ `SUSPENDED`).

> **괴리율 20%를 넘기는 종목은 체결을 한 번만 만든다.** 첫 체결에서 바로 거래가 중단되므로
> (TR-08) 두 번째 체결은 `STATE_NOT_TRADABLE`로 실패한다. 시스템이 맞고 시드가 틀린 경우였다.

## 이중 괴리율 — 이 프로젝트의 핵심 화면

ETF 기초자산 종목의 상세에는 두 괴리율이 나란히 뜬다.

| | 값의 출처 | 유동성공급자 |
|---|---|---|
| **기초자산 ETF 괴리율** | 증권사가 계산해서 준다 (`dprt`) | **있다** — LP 의무호가 |
| **FRACTA 조각 괴리율** | 우리 엔진이 계산한다 | **없다** |

같은 기초자산인데 두 숫자가 다르다. 그 차이가 곧 **유동성공급자 제도의 효과**다.
"조각투자는 유동성이 얕아 가격이 벌어진다"를 말로 설명하는 대신 숫자로 보여준다.

LP 의무호가 잔량을 함께 적는 이유도 그것이다 — 괴리를 좁혀주는 주체가 실재한다는 증거다.

### 그래서 임계치가 거래소보다 공격적이다

ETF는 LP가 괴리를 좁혀준다. 조각투자 플랫폼에는 그 제도가 없다.
**좁힐 수단이 없으니 벌어지면 멈추는 수밖에 없다** — ±20% 자동 거래중단(TR-08)은
임의의 숫자가 아니라 이 제도적 결핍에서 도출된 결정이다.

## NAV는 `Output_3`에 있다

`etfCurrent` 응답은 5개 블록으로 나뉜다. 처음에 `Output_0`만 보고
"NAV 필드가 비어 있다"고 잘못 읽었다(2026-09-03).

| 블록 | 내용 |
|---|---|
| `Output_0` | 현재가·10호가·거래원 (131개 항목) |
| `Output_1` | 최근 체결 |
| `Output_2` | 예상체결 |
| **`Output_3`** | **NAV · 괴리율 · 추적오차 · LP 의무호가 잔량** |
| `Output_4` | 기초지수 |

실측값 (069500 KODEX 200):

```
itmt_last_nav  104,015.71   장중 NAV
dprt                  0.2   괴리율 (%)
trc_errt             0.38   추적오차율 (%)
lp_askp_rsqn1..10   8,543   LP 매도 의무호가 잔량 합
lp_bidp_rsqn1..10  38,584   LP 매수 의무호가 잔량 합
```

## 기본 구현은 비어 있다

`NoEtfReferenceAdapter`는 항상 `Optional.empty()`를 준다. **NAV를 Mock으로 지어내지 않는다.**

지어내면 "증권사 값과 우리 계산을 대조한다"는 검증이 **자기 자신과의 대조**가 되어
아무것도 증명하지 못한다. 없으면 없다고 하는 편이 정직하고, 화면도 그때는
조각 괴리율만 보여준다.

## 종목 검색 — 마스터는 로컬, 시세는 API

PLUG에는 이름으로 종목을 찾는 API가 없다. 모든 시세 API가 종목코드를 받는다.
그래서 NH가 공개 배포하는 종목마스터(`m_new_stock.mst`)를 받아 DB에 둔다.

```
검색어 → DB 문자 검색 (LIKE)
           ↓ 0건이면
        로컬 임베딩 의미 검색 (bge-m3)
           ↓
        종목코드 확보
           ↓
        PLUG 시세 API  ← 선택한 하나만
```

**목록에서는 시세를 부르지 않는다.** 30건을 조회하면 실효 한도 1건/초에 바로 걸린다.

### LLM을 쓰지 않는 이유

의미 검색에 LLM을 쓰면 **없는 종목코드를 지어낼 수 있다.** `069500`을 `069510`으로
한 글자만 틀려도 엉뚱한 종목 시세가 화면에서는 정상처럼 보인다.

로컬 임베딩은 마스터 안에서만 고르므로 **존재하는 코드만 나온다.** 호출 비용도 없다.
투자설명서 RAG가 쓰던 bge-m3를 그대로 재사용한다.

실측 — ETF·리츠 1,100종목 인덱싱 56초, LLM 호출 0회.

| 질의 | 방식 | 결과 |
|---|---|---|
| `삼성` | TEXT | 삼성전자 · 삼성전자우 · 삼성전기 |
| `반도체` | TEXT | 한미반도체 · TIGER 반도체TOP10 |
| `코덱스` | SEMANTIC | KODEX 반도체 · KODEX IT · KODEX 인버스 |
| `나스닥 따라가는거` | SEMANTIC | PLUS 미국나스닥테크 · 1Q 미국나스닥100 |
| `물류 부동산` | SEMANTIC | TIGER 리츠부동산인프라 · KODEX 한국부동산리츠인프라 |

문자로 잡히면 임베딩을 태우지 않는다. "삼성"처럼 정확히 맞는 질의까지 벡터 검색을 돌리면
느려지고 결과도 흐려진다. 응답의 `matchedBy`가 어느 경로였는지 알려주므로,
사용자가 친 글자가 결과에 안 보여도 화면이 이유를 설명할 수 있다.

## 정직하게 남기는 한계

- **ETF를 조각내 파는 사업은 현행법상 인가 문제가 남아 있다.** 이 프로젝트는
  "그 제도가 생긴다면"의 기술 구현이다.
- ETF는 이미 소액 분산 상품이라 조각화 니즈 자체는 리츠·실물자산이 더 크다.
  ETF를 쓰는 진짜 이유는 **정답지**이기 때문이다.
- 증권사 MTS에는 소수점 거래가 있다(신청 기반). 확인한 것은
  **오픈 API에 조각 거래 수단이 없다**는 것이고, 그래서 API 소비자가 조각 거래를
  만들려면 자체 원장과 오더북이 필요하다.
- 모의 자산 61건은 이름만 만든 것이다. 실제 감정평가·수익률 데이터는 없다.
