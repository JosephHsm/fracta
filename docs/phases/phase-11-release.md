## 데모 시나리오 (권장 흐름)

```
1. docker compose up  — 한 번에 전체 기동
2. 투자자 가입 → KYC → 투자성향 진단(공격투자형)
3. ADMIN: 기초자산 등록 → 발행 계획 → 투자설명서 업로드 → 승인
4. 투자설명서 AI 질의
   - 정상 질문 → 인용 포함 답변
   - "이거 사도 될까요?" → 가드레일 차단 시연  ★
5. 청약 (경쟁률 초과 상황) → 비례배분 결과 확인
6. 상장 → 유통 시장에서 매매
7. 괴리율 20% 초과 유도 → 자동 거래 중단 시연  ★
8. 개발자 포털: 앱 등록 → 샌드박스 호출 → 쿼터 초과 429 시연  ★
9. 웹훅 수신 확인 (서명 검증 포함)
10. 배치: 데이터 훼손 → 대사 배치 검출 시연  ★
11. AI_PROVIDER=ollama 전환 후 동일 질의  ★
```

★ 표시는 **차별 포인트**다. 영상에서 반드시 포함한다.

## 흔한 실수

1. **비교표를 추정치로 채움** → 실측 데이터가 없으면 항목을 빼는 게 낫다. 거짓은 면접에서 바로 드러난다
2. 아키텍처 다이어그램에 미구현 컴포넌트를 그림 → 질문받으면 무너진다
3. 트러블슈팅 로그를 Phase 11에 몰아서 씀 → 기억이 안 난다. **각 Phase에서 그때그때 기록**
4. 한계·미구현을 숨김 → 오히려 신뢰를 잃는다. 명시하고 왜 그렇게 결정했는지 적는다
5. API 키가 커밋 이력에 남음 → `git log -p | grep` 으로 최종 확인
6. 데모 영상이 너무 길다 → 차별 포인트 5개(★) 중심으로 5~8분
7. README가 기능 나열에 그침 → **의사결정과 근거**가 핵심이다
