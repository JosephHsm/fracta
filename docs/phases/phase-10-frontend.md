# Phase 10 — 프론트엔드

> 기간 2주 · 선행 Phase 7 · FSD 참조 §11, §6.5, §10

## 목표

투자자 웹앱과 개발자 포털 2개를 만든다. 백엔드가 만든 차별 포인트(괴리율, 가드레일, 쿼터)가 **화면에서 보여야** 포트폴리오 가치가 생긴다.

## 범위

**포함**
- 모노레포 구성 (`apps/investor-web`, `apps/dev-portal`, `packages/ui`, `packages/api-client`)
- investor-web 7개 화면
- dev-portal 6개 화면
- OpenAPI Generator 기반 타입 클라이언트

**제외**
- 모바일 네이티브 앱 (FSD §1.4 명시적 비목표)
- 다국어 (FSD §1.4 명시적 비목표)
- 실시간 차트 라이브러리 자체 구현 (기존 라이브러리 사용)

## 구성 (FSD §11.1)

```
apps/
├── investor-web/     # 투자자용
└── dev-portal/       # 개발자용
packages/
├── ui/               # 공용 컴포넌트
└── api-client/       # 타입 생성 클라이언트 (OpenAPI Generator)
```

- Next.js 16 (App Router) + TypeScript
- Tailwind CSS v4 + shadcn/ui — 프리미티브는 **Base UI** (shadcn이 2026-07부터 신규 프로젝트 기본을 Radix → Base UI로 전환). 아이콘 Lucide
- 서버 상태는 TanStack Query, 표는 TanStack Table
- 차트는 기초자산 시세/캔들 = lightweight-charts, 대시보드 지표 = Recharts
- `packages/api-client`는 Phase 7이 생성한 OpenAPI 스펙에서 **자동 생성**. 수동 작성 금지
- `packages/ui`가 디자인 토큰(OKLCH)·모션 스케일·다크 모드의 **단일 소유자**. 앱에서 색상 리터럴 사용 금지

## 디자인 시스템 & 요소 기술 (FSD §11.4)

컨셉은 **Institutional Fintech + Modern SaaS**. 채택 요소 기술은 8개이며, 각각 "왜 썼는지" 설명 가능한 것만 남겼다.

| # | 요소 기술 | 적용 지점 |
|---|---|---|
| 1 | Bento 대시보드 레이아웃 | 홈 / 내 자산 / dev-portal 대시보드 |
| 2 | 마이크로 인터랙션 | 청약·주문 버튼 상태 전이, 테이블 행 진입, 진행률 |
| 3 | View Transitions API | 종목·상품 리스트 → 상세 (Next.js 16 내장, 플래그 불필요) |
| 4 | Container Queries | `packages/ui` 카드·패널 — 부모 폭 기준 반응형 |
| 5 | Subtle Glass 서피스 | 스티키 헤더·모달·플로팅 **한정** |
| 6 | OKLCH 디자인 토큰 | `packages/ui` 토큰 정의 (Tailwind v4 기본 색공간) |
| 7 | 다크 모드 | 라이트 기본 + 다크(트레이딩·모니터링) |
| 8 | 커맨드 팔레트 `Ctrl+K` | 종목·명령 검색 (두 앱 공통) |

선택 적용: CSS Anchor Positioning(툴팁·팝오버). Baseline 2026 *newly available*이라 지원 편차가 있다 — **`@supports` 폴백 없이 쓰지 말 것**. Base UI 팝오버의 JS 위치 계산이 기본 경로이고 anchor positioning은 점진적 향상으로만 얹는다.

**모션 스케일** (초과 금지)

```
hover  100~150ms     button 150~200ms
panel  200~300ms     page   250~400ms
```

`prefers-reduced-motion: reduce`에서 View Transition·카운트업·행 진입 애니메이션을 전부 끈다.

**배제** — WebGL/3D 메인, 전면 글래스모피즘, 네오 브루탈리즘, 전방위 애니메이션, 운영자 성능 벤치마크 화면(범위 밖. 수치는 Phase 11 README).

## investor-web 화면 (FSD §11.2)

| 화면 | 내용 | 핵심 |
|---|---|---|
| 홈 | 청약 중 / 상장 종목 리스트 | |
| 종목 상세 | 발행 정보, 기초자산 시세 차트, **괴리율 배지**, 호가창, 체결 내역 | ★ 괴리율 배지가 이 프로젝트의 얼굴 |
| 투자설명서 | PDF 뷰어 + **AI 질의 사이드패널** | ★ 인용 클릭 시 해당 페이지로 이동 |
| 청약 | 수량 입력 → 증거금 확인 → 적합성 경고 → 신청 | ★ 적합성 차단 UX |
| 주문 | 지정가/시장가, 호가 클릭 시 자동 입력 | |
| 내 자산 | 보유 조각, 평가금액, 손익, 거래 내역 | |
| 온보딩 | 가입 → KYC → 투자성향 진단 | 8문항 설문 UI |

### 필수 UX 규칙

- **괴리율 배지**: 정상(회색) / 경고 ±10% 초과(주황) / 중단 ±20% 초과(빨강 + "거래 중단" 표시)
- **적합성 차단**: `403 SUIT_PROFILE_MISMATCH` 수신 시 사유를 명확히 표시하고, 확인 서명 동선을 제공한다. 조용히 실패시키지 않는다
- **금액 표시**: 서버가 준 값을 그대로 표시. 프론트에서 `Number` 연산으로 금액을 재계산하지 않는다 (부동소수점 오차). 카운트업 애니메이션도 **금액에는 금지** — 진행률·경쟁률 같은 파생 지표에만 쓴다
- **인용 클릭**: AI 답변의 `[p.12]` 클릭 → PDF 뷰어가 12페이지로 스크롤
- **등락 색**: 국내 관행대로 **상승 = 적색, 하락 = 청색**. 서구식 반전 금지. 괴리율 배지의 경고(주황)·중단(빨강)은 등락과 다른 축이므로 아이콘 + 텍스트를 함께 붙여 혼동을 막는다
- **접근성**: WCAG 2.2 AA. 색만으로 상태를 전달하지 않는다(1.4.1). 키보드만으로 온보딩 → 청약 → 주문 전 동선 도달, `:focus-visible` 상시 노출
- **AI 사이드패널**: 채팅 버블만 늘어놓지 않는다. Phase 8의 구조화 출력(근거 문단·인용 `[p.N]`·신뢰도)을 **근거 카드**로 렌더한다. 새 응답 필드를 프론트 편의로 요구하지 말 것 — 백엔드 계약은 Phase 8에서 고정됐다

## dev-portal 화면 (FSD §11.3)

| 화면 | 내용 |
|---|---|
| 대시보드 | 호출량 그래프, 쿼터 사용률, 에러율 |
| 앱 관리 | 클라이언트 등록, 키 발급/재발급, Scope 설정 |
| API 문서 | Swagger UI 임베드 + **AI 어시스턴트 챗** |
| 샌드박스 | 브라우저에서 바로 호출해보는 콘솔 |
| 웹훅 | URL 등록, 시크릿 확인, 발송 이력 및 재발송 |
| 로그 | 호출 로그 검색 (엔드포인트·상태코드·기간) |

### 필수 UX 규칙

- **`client_secret`은 발급 직후 1회만 표시.** 이후 화면에서는 마스킹. "다시 볼 수 없습니다" 경고 필수
- **쿼터 사용률**은 `X-RateLimit-*` 헤더 기반 실시간 표시
- **샌드박스 콘솔**은 LIVE 키로 호출 불가하게 UI에서 차단

## 구현 순서

1. 모노레포 스캐폴딩 (Turborepo 또는 pnpm workspace)
2. `packages/api-client` — OpenAPI Generator 파이프라인 구축 (스펙 변경 시 재생성 스크립트)
3. `packages/ui` — **먼저 토큰**(OKLCH 색·타이포·모션 스케일·다크 모드)을 잡고, 그 위에 공용 컴포넌트 (버튼, 폼, 테이블, 배지, 토스트, 커맨드 팔레트). 카드·패널은 Container Query 기준으로 작성
4. investor-web: 온보딩 → 홈(Bento) → 종목 상세 → 청약 → 주문 → 내 자산 → 투자설명서
5. dev-portal: 앱 관리 → 대시보드 → 샌드박스 → 웹훅 → 로그 → API 문서
6. View Transition 연결 (리스트 → 상세) 및 마이크로 인터랙션 마감
7. 반응형·접근성 점검 (WCAG 2.2 AA, 키보드 동선, `prefers-reduced-motion`)
8. 에러 처리 일관화 (FSD §7.1 에러 코드 → 사용자 문구 매핑표)

### 요소 기술 (FSD §11.4)

- [ ] 색상 리터럴이 앱 코드에 0건 — 전부 `packages/ui`의 OKLCH 토큰 경유

- [ ] 리스트 → 상세가 View Transition으로 이어짐
- [ ] `prefers-reduced-motion: reduce`에서 View Transition·카운트업·행 진입이 전부 꺼짐
- [ ] 카드 컴포넌트가 뷰포트가 아니라 **부모 폭**에 따라 레이아웃을 바꿈 (Container Query — 넓은 영역 / 사이드바 양쪽 확인)

- [ ] `Ctrl+K` 커맨드 팔레트로 종목 검색·주요 화면 이동 가능, 키보드만으로 조작됨
- [ ] Glass 효과가 스티키 헤더·모달·플로팅 외 요소에 쓰이지 않음
- [ ] anchor positioning을 쓴 팝오버가 미지원 브라우저에서도 정상 배치됨 (`@supports` 폴백)
- [ ] 키보드만으로 온보딩 → 청약 → 주문 완주 가능, 포커스 링이 항상 보임

## 흔한 실수

1. API 클라이언트를 손으로 작성 → 스펙 변경 시 조용히 어긋난다. **반드시 자동 생성**
2. 금액을 프론트에서 `price * units`로 재계산 → 부동소수점 오차. 서버 값 그대로 표시
3. 적합성 차단을 일반 에러 토스트로 처리 → 금소법 시연 포인트를 날린다. 전용 UI 필요
4. `client_secret`을 상태에 보관해 재렌더 시 다시 노출 → 1회 표시 원칙 위반
5. 괴리율 배지를 단순 숫자로만 표시 → 시각적 경고가 핵심이다. 색상 단계 필수
6. 실시간 호가를 폴링으로 구현 → WebSocket 또는 SSE 사용 검토 (최소한 폴링 간격 명시)
7. 에러 코드를 그대로 화면에 노출 → 매핑표 필수
8. 요소 기술을 "유행이라서" 전부 넣기 → fade·slide·zoom·bounce·parallax를 다 넣으면 오히려 싸 보인다. §디자인 시스템의 8개 + 선택 2개 밖으로 나가지 말 것
9. 다크 모드를 색 반전으로만 처리 → 괴리율 배지·등락 색 대비비가 깨진다. 토큰을 라이트/다크 각각 정의
10. anchor positioning을 폴백 없이 사용 → 미지원 브라우저에서 팝오버가 화면 밖에 붙는다
11. 금액에 카운트업 애니메이션 → 중간 프레임이 서버가 주지 않은 금액이다. 진행률에만 사용
