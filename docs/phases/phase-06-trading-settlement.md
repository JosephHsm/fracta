# Phase 6 — 유통·결제

> 기간 1.5주 · 선행 Phase 4, 5 · FSD 참조 §6.5, §6.6, §8.4, §5.2

## 목표

오더북 매칭 엔진과 DvP 결제를 구현한다. **증권만 넘어가고 대금이 안 넘어가는 상태가 단 한 순간도 존재해서는 안 된다.**

## 범위

**포함**
- 지정가/시장가 주문, 주문 취소
- 매칭 엔진 (가격 우선 → 시간 우선)
- 오더북 재시작 복원
- DvP 결제, 수수료
- 괴리율 계산·저장·경보
- 정산 리포트 (집계 로직만, 배치 스케줄은 Phase 9)

**제외**
- 오픈 API 노출 (Phase 7)
- 배치 스케줄링 (Phase 9)
- 프론트 호가창 UI (Phase 10)

## 핵심 사양

### 매도 주문 시 수량 잠금 (TR-01) ★

```
매도 주문 접수 → LedgerPort.lock(symbol, seller, units, TxRef(EXECUTION, orderId))
                → 성공해야만 주문 레코드 생성
주문 취소     → LedgerPort.unlock(미체결 잔량)
```
- **이 순서를 지키지 않으면 이중 매도가 발생한다** (FSD 부록 B-3)
- 잠금과 주문 생성은 동일 트랜잭션

### 매칭 엔진 (§8.4)

```
매수: PriorityQueue — 가격 내림차순, 동가면 시각 오름차순
매도: PriorityQueue — 가격 오름차순, 동가면 시각 오름차순

1. 신규 주문 도착
2. while (반대편 최우선 호가와 교차 && 잔량 > 0):
     체결가 = 먼저 들어온 주문의 가격   (Price-Time Priority)
     체결량 = min(양측 잔량)
     체결 기록 생성 → DvP 결제 호출
     잔량 차감, 0이면 큐에서 제거
3. 잔량이 남고 LIMIT → 큐에 삽입
   MARKET → 잔량 취소
```

**동시성**
```
종목별 단일 스레드. 종목 심볼 해시로 스레드 풀 파티셔닝.
→ 같은 종목의 주문은 항상 같은 스레드에서 순차 처리
→ 오더북 자체에는 락 불필요
```
- 파티션 수는 설정값. `Math.floorMod(symbol.hashCode(), partitions)`
- **`hashCode()`가 음수일 수 있으므로 `floorMod` 필수** (`%`는 음수를 반환)

### 오더북 복원 (★ 필수)

```java
@PostConstruct  // 또는 ApplicationReadyEvent
void restore() {
    // DB에서 status IN ('OPEN','PARTIALLY_FILLED') 주문을 조회
    // created_at 오름차순으로 큐에 재삽입 → 시간 우선순위 보존
}
```
- 인메모리 오더북은 재시작 시 사라진다. 복원 없으면 **미체결 주문 유실**
- 복원 후 잠금 수량과 원장 `locked_units` 정합성을 검증하고, 불일치 시 부팅 실패 또는 경보

### DvP 결제 (ST-01) ★★

```
동일 트랜잭션 내에서:
  1. 락 획득 — 항상 owner_id 오름차순  ← 데드락 방지, 순서 절대 고정
  2. 매수자 cash_balance -= 체결금액 + 매수 수수료
  3. 매도자 cash_balance += 체결금액 - 매도 수수료
  4. LedgerPort.unlock(매도자, 체결량)
  5. LedgerPort.transfer(매도자 → 매수자, 체결량)
  6. trade_execution 기록
어느 하나라도 실패 → 전체 롤백 → 주문 REJECTED + 잠금 해제
```

- **락 획득 순서를 `owner_id` 오름차순으로 고정하지 않으면 데드락** (FSD 부록 B-9)
- 수수료: 체결금액 × 0.015%, **원 단위 절사** (`RoundingMode.DOWN`), 매수·매도 각각
- 수수료 계산도 `Money` 경유. `double` 금지
- 매수자 잔액 부족 시 → 주문 `REJECTED`, 매도자 잠금 유지 (매도 주문은 살아있다)

### 괴리율 (TR-07, TR-08) ★ 차별 포인트

```
조각 참조가 = round(원자산 현재가 / 분할비율)      ← Phase 5 PriceConverter
괴리율     = (체결가 - 조각 참조가) / 조각 참조가 × 100

체결 시점에 산출하여 trade_execution.premium_rate 에 저장
```

**경보 (TR-08 — 반드시 구현)**
```
|괴리율| > 10%  → 경고 (로그 + 메트릭 + 이벤트)
|괴리율| > 20%  → 해당 종목 자동 SUSPENDED + token.suspended 이벤트
```
- `SUSPENDED` 전이 시 신규 주문 접수 거부, 기존 미체결 주문 처리 규칙을 **명시적으로 결정하고 문서화**
  → **권장: 미체결 주문 전량 취소 + 잠금 해제** (거래 중단의 의미에 부합)
- 원자산 시세 미조회 상태면 괴리율 계산·경보를 **건너뛴다** (Mock 어댑터에서도 동작해야 함)

## 구현 순서

1. Flyway `V6__trading.sql` — `trade_order`, `trade_execution` (+ `idempotency_key` UNIQUE)
2. `OrderBook` 자료구조 + 매칭 알고리즘 **순수 단위 테스트 먼저** (DB 없이)
3. 파티셔닝된 단일 스레드 실행기 (`OrderBookExecutor`)
4. 주문 접수 유스케이스: 적합성 → (매도면) 잠금 → 주문 생성 → 매칭 큐 투입
5. `SettlementService.settle(execution)` — DvP
6. 수수료 계산 (순수 함수 + 절사 테스트)
7. 주문 취소 (TR-03) — 미체결 잔량만, 잠금 해제
8. 괴리율 계산·저장 (TR-07)
9. 괴리율 경보 + 자동 `SUSPENDED` (TR-08)
10. 호가창 10호가 조회 (TR-05), 체결 내역 페이징 (TR-06)
11. 오더북 복원 (`@PostConstruct`)
12. 정산 집계 로직 (ST-04)

## 흔한 실수

1. **매도 시 수량 잠금 누락** → 이중 매도 (부록 B-3)
2. **오더북 재시작 복원 누락** → 미체결 주문 유실 (부록 B-4)
3. **DvP 락 획득 순서 미고정** → 데드락 (부록 B-9)
4. `symbol.hashCode() % partitions` 사용 → 음수 인덱스. `Math.floorMod` 필수
5. 체결가를 신규 주문 가격으로 사용 → Price-Time Priority 위반. **먼저 들어온 주문의 가격**
6. 수수료를 `double`로 계산 후 캐스팅 → 부동소수점 금지 위반
7. DvP를 매칭 스레드에서 동기 호출하며 트랜잭션 경계를 domain 레이어에 둠 → `@Transactional`은 **application 레이어에만**
8. 괴리율 산출 시 원자산가 0 → 0으로 나누기. 방어 필수
9. `SUSPENDED` 전이 후 기존 미체결 주문 처리를 정하지 않음 → 잠금이 영구히 남는다
10. 매칭 스레드 풀에서 예외를 삼킴 → 오더북이 조용히 멈춘다. 예외 핸들러 + 메트릭 필수
